# 立项评估（点子值不值得做）

用于「这个想法怎么样」「要不要立项」「帮我压力测试一下」，输出 GO / ITERATE / STOP 与证据。只做评估，不写 PRD；评估通过再进 PRD 流程。

## 一、存在性校验（前置，不可跳）

1. **问题**：具体痛点，用户自己的表述，带发生频率。
2. **用户**：有名有姓的群体——岗位、规模、处境。「大家」「企业」「年轻人」不算通过。
3. **证据**：至少一个真实信号——访谈原话、工单量、竞品定价页、用户自建的表格/脚本。

三项缺两项 ⇒ 不评分，只列缺什么并索取。缺证据时给出的分数是「建立在空地上的自信」，比没有分析更糟。

## 二、竞争扫描（评分前必做）

| 类型 | 要查什么 |
|------|---------|
| 直接竞品 | 2-3 家，定价、规模、进入市场年数、明显短板 |
| 替代方案 | 用户现在拿什么凑合（表格 + 群聊 + 手工流程），凑合越普遍信号越强 |
| 平台风险 | 哪个巨头一次版本迭代就能把这个功能内置掉 |
| 墓地 | 有没有做过并失败的产品；失败原因今天是否已改变（不是否决项，但必须解释） |

没有竞品不等于机会，多数时候等于没有市场；按弱评并说明。数据不足时标 `[缺数据]`，不要估一个 TAM 当事实。

## 三、五维评分

每维评 强 / 中 / 弱，每维 2-4 句理由。**评「强」必须有名有姓的对照、具体数字或观察到的用户行为**，否则降档。

| 维度 | 看什么 |
|------|--------|
| 问题严重度 | 频率、现状成本、是否已有自发的替代方案 |
| 市场证据 | 谁已经在付钱、付多少、市场在涨还是在缩 |
| 差异点 | 切入点是什么，能否守住（数据、渠道、生态、成本） |
| 可行性 | 小团队 4-6 周能否做出可用版本，最难的一步是什么 |
| 商业可行性 | 谁付钱、付多少、路径到可持续收入 |

判定：4 项以上强 ⇒ GO；1-2 项需补且方向可调 ⇒ ITERATE 并写明具体转向；底层问题无法靠转向解决 ⇒ STOP。不要因为用户热情而软化 STOP，结论就是交付物。

## 四、输出格式

```markdown
## 结论：GO / ITERATE / STOP
[两句：决定 + 唯一主要理由。]

## 评分
| 维度 | 评级 | 一句理由（含证据） |

## 竞争格局
[表格：竞品/替代 | 类型 | 定价 | 规模 | 短板]

## 理由
[每维 2-4 句，带数字或可核实事实]

## 关键问题
[3 个最可能推翻结论的问题，指向最弱的两维]

## 下一步（选 3 个最快最便宜的动作）
- 动作：…　成本：…　信号：什么结果会提高/降低信心

## 假设与缺口
[所有 [假设] / [缺数据] / [待确认] 汇总]
```

## 五、常见偷懒

| 想法 | 为什么不行 |
|------|-----------|
| 用户很兴奋，结论给 GO | 软化的结论让人多花半年 |
| 没有竞品，是蓝海 | 多数是没市场，按弱评 |
| 没有数据，估个市场规模 | 估算数字会被当作事实使用，写 `[缺数据]` |
| 四项强一项弱，四舍五入 GO | 那一项弱通常正是致命项；商业可行性弱最多到 ITERATE |
| 验证完下一步是搭原型 | 下一步通常是需求测试（预售、落地页、手工服务），不是开发 |
| 只做评分，不写关键问题 | 关键问题才是用户真正需要面对的部分 |

## 六、市场规模（TAM / SAM / SOM）

无来源时**只给口径与采集计划，不给数字**。以下同样算编造：凭「公开信息记忆值」「行业常识估算」「大致区间」给出的规模数字。

允许的三种输出：
1. **缺数据版（默认）**：写清 TAM/SAM/SOM 的定义、口径边界（算进什么、不算什么）、需要的 5 项数据源、自下而上的公式（席位 × ARPU 之类）——**公式里留空**，不填猜测值。
2. **有来源版**：每个数字标来源（报告名 + 年份 + 可访问链接或页码）；拿不到原文就标 `[缺数据]`。
3. **敏感性框架**：只给「参数 → 结果」的表格模板，参数列为空，让用户自己填或后续补。

硬规则：
- 不得把「视频会议大盘」「行业总规模」直接当 TAM；必须写清增量口径。
- 任何规模数字出现时，同一段必须写明「口径 + 来源 + 采集日期」；缺任一项即视为编造。
- 用户要求「算一个 TAM 写进 BP」时，先回「缺哪些数、怎么取」，而不是先给数。
- 禁止把估算标注成「🟡 需复核」后就当结论交付——标注不改变「数字是编的」这一事实。

## 七、实验优先级

按「最快 + 最便宜 + 最能改变判断」排序，优先选不写代码就能拿到信号的：访谈 5 个目标用户、手工完成一次服务、落地页收预约、竞品报价对比、内部数据回溯。每个实验写清成本与判定信号，避免「做了个原型所以算验证过了」。
