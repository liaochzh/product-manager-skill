# 多形态 PRD（形态 × 尺寸类 × 验收）

> 一层深引用：只服务 `product-manager`。规范口径（断点数值、平台硬规则）以 `design-spec/references/ui-design-philosophy.md` §自适应布局 / §形态与共存 为唯一权威源，本文件**不复制断点数值**，只写「PRD 里要写什么、怎么验收、怎么交给原型层」。

## 1. 何时需要本文件

- PRD 的**平台**一栏出现「平板 / 折叠 / 多窗口 / 响应式 / 一套适配多端」之一时。
- 产品有**大屏高价值场景**（列表 + 详情同屏、看板多列、播放器横屏、分屏对账）。
- 用户要求「一个 App 适配多形态」或明确要 iPad / Android 平板验收。

不需要时：纯手机单形态产品，平台三问里答「仅手机」即可，本节整体 N/A（写明理由，不要静默省略）。

## 2. 平台与形态是两个维度（阶段一必问）

| 维度 | 取值 | 说明 |
|---|---|---|
| 平台 | iOS / Android / Web / 桌面端 / 小程序 | 决定**结构与系统行为**（导航、返回、权限、字体） |
| 形态 | 手机 / 平板 / 折叠（外屏·内屏·半折）/ 多窗口（分屏·自由窗口） | 决定**可用空间与伴随事件** |

「平台」与「形态」不可互相替代：写「移动端」不等于覆盖平板；写「iPad」也不等于换平台。两者都要落字。

## 3. 形态矩阵（完整档必含；1 页档用无序列表并入「方案范围」）

| 形态 | 尺寸类 | 布局范式 | 关键页差异 | 验收断言 |
|---|---|---|---|---|
| 手机（竖） | compact | 单列 + 底部 TabBar | 基线稿 | 主操作首屏可达；无横向溢出 |
| 手机（横） | compact（高度不足） | 单列，**不因变宽改双栏** | 播放/地图类全屏 | 横屏核心内容不被裁；安全区左右独立 |
| 平板（竖/横） | medium / expanded | 单列或 list-detail（列表 + 详情同屏） | 列表页常驻左栏 | 双栏均可操作；窄窗（1/3 分屏）不塌 |
| 折叠外屏 | compact | 单列 + 侧边控制条 | 与外屏比例不同 | 不出现旧比例的上下黑边（letterbox） |
| 折叠内屏（展开） | medium / regular | 双栏 | 首页/详情同屏 | 折痕区不放关键内容与可点元素 |
| 折叠半折（tabletop / book） | 按可用区 | 展示区 / 操作区分区 | 视频、会议类 | 交互元素远离铰链；姿态切换不丢状态 |
| 多窗口 / 分屏 | 按窗口宽 | 同对应尺寸类 | — | 50% 分屏与 1/3 分屏主操作不被遮挡 |

**写法要求**：矩阵只写「形态 + 尺寸类 + 范式」，**不写具体断点像素**（断点归规范层，写死会在机型换代时过期）。每条差异必须能落到一个**可观测断言**，否则删掉——「体验更好」不是断言。

## 4. 折叠姿态与连续性（写进「方案范围」而非附录）

- **状态连续**：开合、分屏拖动、窗口缩放后，滚动位置、已填输入、选中项、播放进度、导航栈保持；PRD 要写明「哪些状态必须保住」。
- **不重建结构**：布局在尺寸类之间切换时只改容器与排布，**不得把内容从原父节点摘出再包进新容器**（会导致子状态重建、播放/长连接中断）。写进验收，别留给实现猜。
- **不 letterbox**：不保留旧比例的上下黑边。
- **避让由系统承担**：折痕/铰链/摄像头区的避让走 safe area 与保留区，**不要在 PRD 里要求页面自绘折痕带**；自绘折痕只属设备外观预览。

## 5. Web 底线（H5 / 响应式）

- **320px 不横向滚动**（reflow 底线）；内容按容器宽度重排，不按 UA / 屏幕宽分支。
- 平板与桌面用**容器查询**做组件级断点；窗口宽是范围不是承诺（1/3 分屏、自由窗口）。
- 触屏必须有等价可见反馈，hover 不作唯一反馈；输入字号不小于 16px（防 iOS 聚焦缩放）。

## 6. 形态 → 原型生成参数（交给 `product-prototype-generation`）

| 要演示的形态 | 生成参数 |
|---|---|
| 手机基线 | `--platform mobile --device iphone16`（或 `iphone16-pro-max`） |
| 平板 | `--platform mobile --device ipad-air-11` / `ipad-pro-13` / `android-tablet` |
| 折叠外屏 / 内屏 | `--device iphone-duo-cover` / `iphone-duo-inner`（或 `zfold7-*` / `matext-*`） |
| 折叠半折姿态 | `--device iphone-duo-inner --posture half`（`flat` 展开无带 / `closed` 闭合） |
| 一套多形态并排预览 | `--frame-set iphone16,ipad-air-11,iphone-duo-inner:half`（≤4 帧，另出 `gallery.html`） |
| 桌面端 | `--platform desktop` |

**契约提醒**：多帧产物是**形态容器**，只演示外壳几何与可用空间，**不代表页面已按断点重排**；PRD 里不要写成「已适配大屏」，只能写「已完成形态覆盖，页面级重排见二期」。`--posture` 是预览参数，不得表述为「运行时能判定姿态」。

## 7. 交付契约按档落位

| 档位 | 形态矩阵怎么写 |
|---|---|
| 完整 PRD | 必备：§3 矩阵表 + §4 连续性验收 + 形态→参数映射；缺一项即视为未覆盖多形态 |
| 1 页 PRD | 以**无序列表**并入「方案范围」段（例：`- 形态：手机 / 平板 / 折叠内屏；平板走双栏，折叠半折按上下分区`），**不新增表格**（守住「至多 2 张表」） |
| speclet | **不含**形态矩阵；只在开放问题里问「要不要覆盖平板/折叠」 |

## 8. 自检（交付前过一遍）

- [ ] 平台与形态**两维都落字**，没有用「移动端」笼统覆盖。
- [ ] 矩阵每条差异都有可观测断言；没有写死断点像素。
- [ ] 连续性（保什么状态）与「不重建结构」写进了验收，不是隐含期望。
- [ ] 未要求页面自绘折痕避让。
- [ ] Web 侧写了 320px 不横滚。
- [ ] 档位与矩阵落位自洽（1 页档没有偷偷加表）。
